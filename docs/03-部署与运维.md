**踩坑记录（重要，下次建站直接照做）**：Pages 自定义域的证书走 **HTTP-01 校验**（访问 /.well-known）。若在建域**之前**就开启 Always Use HTTPS 或根域 301，校验请求被拦截，域会永久卡在 pending。正确顺序：

1. zone active + DNS 就绪 → **先**加 Pages 自定义域，等两域名 active、证书签出（约 2–5 分钟）
2. **再**开 Always Use HTTPS 和 301 规则

若已经卡 pending：关掉这两项 → DELETE 再 POST 一次 Pages 域名（重新触发校验）→ active 后恢复。

API Token（`easell-dns`）权限：Zone:Edit / DNS:Edit / Zone Settings:Edit / Single Redirect:Edit，All zones。token 存于 `scripts/.cf_api_token`（已 gitignore，勿提交）。wrangler OAuth 无 zone 写权限，zone/DNS/设置操作一律用这个 token。



Cloudflare Pages 的 GitHub App 是"选定仓库"授权。新仓库要进安装范围：
https://github.com/settings/installations → **Cloudflare Pages** → Configure → Repository access 勾选 `easell.com` → Save。

未授权时推送不会自动触发构建（部署记录里没有 `github:push`）；可用 Deploy Hook 手动触发兜底。

### 踩过的三个坑（改配置时别再犯）

1. **`http2 on;` 是 nginx ≥1.25 的语法**，Ubuntu 24.04 的 nginx 1.24 必须写 `listen 443 ssl http2;`，否则 `nginx -t` 直接报 unknown directive。
2. **`location` 里只要出现一条 `add_header`，server 级的全部响应头都会失效**。所以缓存策略统一用 `expires` 指令，安全头只在 server 级写一次。
3. **URL 规范化不能用正则 `location`**（会拦掉 nginx 内部的 index 重定向，导致 `/` 和 `/about/` 自跳转死循环）。必须用 `if ($request_uri ~ ...)` —— `$request_uri` 是客户端原始 URI，不受内部重定向改写。
