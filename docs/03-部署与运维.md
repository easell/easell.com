## 二、域名切换（easell.com 指向 Cloudflare）

当前状态（2026-11-14 实测）：
- NS 在阿里云（dns23/dns24.hichina.com）
- `www` A 记录 → 47.96.152.225（旧 ECS 已到期停机，HTTP 502），**站点实际处于离线状态**

切换步骤（二选一，推荐 A）：

**方案 A（推荐）：NS 整体迁到 Cloudflare**
1. Cloudflare 已建好 zone `easell.com` 与记录（www CNAME → easell-com.pages.dev、根域 CNAME 平滑映射）
2. 老板在阿里云域名控制台把 DNS 服务器改为 Cloudflare 分配的两个 NS
3. 生效后 Pages 自定义域自动激活，HTTP 自动跳 HTTPS

**方案 B：留在阿里云 DNS**
- 在阿里云云解析加一条：`www` CNAME → `easell-com.pages.dev`
- 根域 easell.com 需要用显性 URL 跳转到 www（阿里云根域不支持 CNAME）
- 缺点：根域跳转依赖阿里云 URL 转发，链路多一层

注意：备案号湘ICP备2022019296号-1 当初在阿里云接入。域名解析到 Cloudflare 属境外接入，按工信部规则原备案接入会失效。当前备案号已按老板指令照常上站；若后续要稳妥，重新走一遍备案接入即可。

## 三、GitHub App 授权（一次性，影响自动构建）

Cloudflare Pages 的 GitHub App 是"选定仓库"授权。新仓库要进安装范围：
https://github.com/settings/installations → **Cloudflare Pages** → Configure → Repository access 勾选 `easell.com` → Save。

未授权时推送不会自动触发构建（部署记录里没有 `github:push`）；可用 Deploy Hook 手动触发兜底。

## 四、应急发布（无自动构建时）

```bash
# 推送代码
git push origin main
# 手动触发 Cloudflare 构建（Deploy Hook）
curl -X POST "https://api.cloudflare.com/client/v4/pages/webhooks/deploy_hooks/<hook_id>"
```
