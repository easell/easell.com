### 踩过的三个坑（改配置时别再犯）

1. **`http2 on;` 是 nginx ≥1.25 的语法**，Ubuntu 24.04 的 nginx 1.24 必须写 `listen 443 ssl http2;`，否则 `nginx -t` 直接报 unknown directive。
2. **`location` 里只要出现一条 `add_header`，server 级的全部响应头都会失效**。所以缓存策略统一用 `expires` 指令，安全头只在 server 级写一次。
3. **URL 规范化不能用正则 `location`**（会拦掉 nginx 内部的 index 重定向，导致 `/` 和 `/about/` 自跳转死循环）。必须用 `if ($request_uri ~ ...)` —— `$request_uri` 是客户端原始 URI，不受内部重定向改写。

## SSL 证书：免费 + 自动 + 不会静默失效（2026-11-14 完成 ✅）

### 一句话结论

**Let's Encrypt 免费证书 × 2（ECDSA 主用 / RSA 兜底）+ 续期后自动重载 nginx + 每 6 小时巡检 + 异常推送企微群。**
零费用、零人工、不会出现"某天早上打开网站报证书过期"。

### 为什么"签一张免费证书"不算彻底

免费证书本身不难，难的是它会**在 90 天后失效**。真实世界里翻车的从来不是"没有证书"，而是下面四件事：

| 失效点 | 后果 | 本方案的防守 |
|---|---|---|
| certbot 自动续期失败（跨境链路抖动、80 口被关、跳转规则改了） | 90 天后全站报错，且**没人知道** | 剩余 30 天起自动续，失败带重试；**每 6 小时**巡检，异常推企微群 |
| 续期成功但 nginx 没重载 | 磁盘上是新证书，用户看到的还是旧的，照样到期 | `renewal-hooks/deploy/10-reload-nginx.sh`：续期后 `nginx -t` 通过才 reload |
| 续了但没生效（配置指错路径、证书写坏） | 同上，且极难发现 | 巡检**比对"对外实际下发的证书序列号"与"磁盘证书序列号"**，不一致立即重载并告警 |
| 只有 ECDSA 证书，老设备握手失败 | 部分安卓/老 Windows 打不开，且不报证书错误，直接白屏 | **双证书**：nginx 按客户端能力自动选，现代设备走 ECDSA，老设备落 RSA 2048 |

| 告警出口 | 复用留言服务的 systemd unit 里的企微 webhook（不新增密钥，改一处两处同步） |
| nginx TLS | 仅 TLS 1.2 / 1.3；ECDHE + AEAD 套件；`ssl_session_tickets off`；`ssl_ecdh_curve X25519:prime256v1:secp384r1`；HSTS 1 年 |

### 常用命令（都在服务器上执行）

```bash
# 看一眼现状（不续期）
/opt/easell/bin/ssl-guard.sh --check

# 看巡检历史
tail -30 /var/log/ssl-guard.log

# 强制续期一次（验证链路用；⚠️ 见下方纪律第 2 条）
/opt/easell/bin/ssl-guard.sh --force

# 单独看 certbot 自己的日志
tail -50 /var/log/letsencrypt/letsencrypt.log

# 看定时任务下次执行时间
systemctl list-timers ssl-guard.timer certbot.timer
```

### 实测记录（2026-11-14）

- **真实续期一次**：ECDSA 证书序列号 `0573CCD6…` → `05246D04…`，nginx 对外同步变为新序列号，`/var/log/ssl-guard.log` 有 `deploy-hook: 续期后已重载 nginx` 记录。
- **双证书分流**：ECDSA 客户端拿到 EC 证书、RSA 客户端拿到 RSA 证书（公网实测，序列号各自匹配）。
- **协议矩阵**：TLS 1.0 / 1.1 握手被拒（`Cipher is (NONE)`），1.2 / 1.3 正常，HTTP/2 可用。
- **信任链**：真实客户端 `ssl_verify_result=0`；服务器自身根证书库 `update-ca-certificates` 后同样为 0（此前为 20，属镜像内证书库残缺）。
- **告警链路**：构造失败场景后，企微群收到「证书自动续期失败」卡片。

### 纪律与边界（改配置前必读）

1. **80 端口必须常开**，且 `location /.well-known/acme-challenge/` 必须排在"80→443 全站 301"之前。巡检每次都会真写文件再从公网取回，动了这里会在 6 小时内告警。
2. **不要随手 `--force-renewal`**。Let's Encrypt 限制"**同一组域名 168 小时内最多 5 张**"，双证书会消耗双份额度。正常 `renew` 只在到期前 30 天才签发，日常安全；连续强制会把自己锁住（本次实测就撞到了，证书本身无影响）。
3. **不要配 `ssl_stapling`**。Let's Encrypt 已于 2025 年停止 OCSP 服务，证书里没有 OCSP 地址，配了只会产生无效告警。吊销状态改走 CRL。
4. **HSTS 未加 `includeSubDomains`**。现在没有 HTTP 子域，加了以后万一有子域走 HTTP 会被浏览器锁死。要加必须先把所有子域上 HTTPS。
5. **`/etc/letsencrypt` 权限不要改**，私钥是 root-only；`/var/www/acme` 归 `www-data`。
6. **跨境链路客观不稳**：服务器到 LE 接口实测 RTT 300ms、偶发超时（约 3/10），这是阿里云青岛出海的常态，靠重试消化，不是故障。

### 最坏情况的手动兜底（连续多日续期失败时）

1. 阿里云控制台 → 数字证书管理服务 → 免费证书 → 申请单域名 DV 证书（免费额度内）；
2. 下载 **nginx 格式**，上传到 `/etc/ssl/manual/easell.com/`（新建目录，权限 600）；
3. 把 nginx 配置里两条 `ssl_certificate` 指向该目录，`nginx -t && systemctl reload nginx`；
4. 该证书 90 天有效，期间排查 certbot（`/var/log/letsencrypt`）。

> 注意：手动证书不参与自动续期，**必须在上表巡检告警恢复后再切回 Let's Encrypt**，否则下一次到期无人提醒。

### 新站点复用（一条命令）

```bash
/opt/easell/bin/new-site-ssl.sh molyn.net www.molyn.net
```

脚本会先自检"解析是否指向本机 / 80 口 ACME 通道是否通"，再签 ECDSA + RSA 两张，并打印要贴进 nginx 的配置片段。签完之后 **续期、生效校验、到期告警全部由 `ssl-guard.timer` 自动接管**，不需要为新站点再配任何东西。

## 代码推不上去时的备用通道（2026-11-14 实测可用 ✅）

现象：`git push` 报 `schannel: server closed abruptly` / `CONNECT tunnel failed, response 502` / 直连 21s 超时。
根因不是仓库权限，是 **`github.com:443` 在当前网络下不通**；同机的 `api.github.com` 却可达（实测 0.3s 返回 200）。

于是提供 `scripts/api-push.py`：读本地提交链，用 GitHub **Git Data API** 在远端重建同样的 commit。
因为 author / committer / 时间 / 消息 / 文件内容全部逐字照抄，**重建出的 SHA 与本地一模一样**（实测 `53ba220` 一致），
不会产生分叉，也不会把历史压成一条——网络恢复后 `git push` 照常可用。

```bash
# 演练：只打印将复刻哪些提交，不写远端
python scripts/api-push.py --dry-run

# 真正推送（代理端口随会话轮换，默认自动取环境变量 HTTPS_PROXY；也可显式指定）
GIT_API_PROXY=http://127.0.0.1:<当前端口> python scripts/api-push.py

# 推送成功后让远端跟踪引用归位，git status 才显示 behind/ahead 正常
git update-ref refs/remotes/origin/main <推送后的 SHA>
```

安全边界：

- 令牌取自 `git credential`（host=github.com），**脚本里不落明文**；
- 前置校验「远端 HEAD 必须是本地 HEAD 的祖先」，否则直接拒绝——只能快进，永远不会覆盖别人的提交；
- 遇到 401/403/404/409/422 立即停（永久性错误重试无意义），只有网络类错误才退避重试。

> 该通道只解决"代码备份/版本记录"，**不触发 Cloudflare 构建**（本仓库 Git 连接未授权自动构建），
> 线上发布仍走 `scripts/deploy-aliyun.py`（SFTP 原子切换）。

## 默认站点隔离：不让陌生域名蹭到本站（2026-11-14 体检后修复 ✅）

**问题**：原先 80 口的 easell server 带 `default_server` 且 `server_name` 里有 `_`，等于
**任何域名只要解析到本机 IP，都会拿到一份完整的易采通网站**——测试域、废弃域、别人恶意指过来的域名，
都能免费得到镜像站，搜索引擎抓到就是重复内容。

**修法**：新增 `/etc/nginx/sites-enabled/00-default.conf`（仓库副本 `scripts/server/00-default.conf`）

- 80 / 443 各一个 `default_server`，`server_name _`；
- `location / { return 444; }` —— 不返回任何字节直接断开；
- 80 口保留 `location /.well-known/acme-challenge/ { root /var/www/acme; }` ——
  以后给新域名签 Let's Encrypt 证书仍然可用（`new-site-ssl.sh` 依赖这条通道）；
- easell.conf 的 80 server 去掉 `default_server`，`server_name` 去掉 `_` 与裸 IP。

**关键坑**：`return 444` 写在 **server 级**会在 location 匹配之前生效，把 ACME 路径一起挡死，
表现为"新域名签证书一直失败"。必须写进 `location / { }` 里。

**复验**：

```bash
curl -sk -o /dev/null -w "catch-all=%{http_code}\n" https://127.0.0.1/ -H "Host: any-random.example"   # 期望 000
curl -s  -o /dev/null -w "acme=%{http_code}\n" http://127.0.0.1/.well-known/acme-challenge/hc -H "Host: newdomain.example"  # 期望 200
curl -s  -o /dev/null -w "site=%{http_code}\n" https://www.easell.com/                                  # 期望 200
```

备份在 `/etc/nginx/backup/easell.conf.bak-20261114`。**注意：备份文件不要留在 sites-enabled/ 目录里**，
nginx 会把它当配置一起加载，直接报 `duplicate default server` 起不来。
